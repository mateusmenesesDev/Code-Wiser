1. Vamos mudar nossa arquitetura para api based. Então precisamos criar uma api para nosso app. A api deve ser separada em features, e cada feature deve ter seu próprio router e procedures. Inicialmente, vamos criar um plano de migração para a api based que possa ser implementado gradualmente sem quebrar a aplicação atual. O plano deve ser documentado em um arquivo .md de plano de migração.
2. Vamos adicionar testes e2e em nosso app. Começaremos por uma feature core da aplicação. O teste deve ser o mais real possível, sem mocks a não ser quando estritamente necessário

3. (terminal 3) Vamos criar a feature de localização em que teremos PT-BR e EN. Partes de UI poderá ser localizado de uma maneira padrão de localização. Coisas dinamicas como título de projeto, descrição, sprints, tarefas, etc, deverão ter um campo pt-br e en no banco de dados, ao criar deveremos ter os fields para cada linguagem. Mas antes de definir dessa forma, podemos discutir para encontrar melhores opções
4. Criar feature para admin em que teremos um botão no code review requested que fará acessar o código do PR, via github api ou via agent-browser, ler o código e gerar sugestões de melhoria. O prompt deverá ter foco grande em tornar o código mais senior, podemos até usar agents prontos disponiveis em repos do github.
